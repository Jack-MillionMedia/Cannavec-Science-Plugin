Cannavec Science API

Research-grade cannabis-science briefs — primary-source anchored, GRADE-honest.

One answer, not two endpoints. /api/answer returns a single blended brief: the verified curated core (GRADE'd, retraction-checked) plus citation-checked live breadth (provenance-tagged live_*, reranked) and a cross-source synthesis verdict (STRONG / MIXED / WEAK) — the two tiers kept visibly distinct.

  • GET /api/health — liveness & capability probe
  • GET /api/answer?question=...&blend=true — the single blended brief (curated core + live breadth + synthesis). JSON; &format=markdown for prose.
  • GET /api/answer?question=... — curated core (offline, deterministic). Auto-fallback: a question the curated KB doesn't cover automatically pulls live primary-source findings (disable with &fallback=false)
  • POST /api/answer — body {"question":"...","blend":true}
  • GET /api/discover?query=... — live PubMed / ClinicalTrials.gov (+ opt-in ChEMBL / Europe PMC) fan-out with a cross-source synthesis verdict, when you want the raw frontier view on its own
  • GET /api/rigor?text=... — phytochemistry & banned-pattern audit
  • GET /api/registries — curated-registry inventory

Examples:

curl "/api/answer?question=CBD evidence in Dravet syndrome&blend=true&format=markdown"
curl "/api/discover?query=cannabis melatonin circadian&sources=pubmed,ctgov"

The live tier (?blend=true and /api/discover) authenticates to NCBI via the NCBI_API_KEY environment variable, and live findings are always provisional — provenance-tagged, retraction-checked, and never promoted into the curated grade. The curated core needs no key and works offline.
